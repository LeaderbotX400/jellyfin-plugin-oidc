OIDC RBAC Configuration

OpenID Connect and SAML single sign-on with role-based access control.

Grant mappings apply permissions. Deny mappings (toggle below) strip permissions after all grants — deny wins.

SAML 2.0 SP-initiated SSO (HTTP-Redirect + HTTP-POST). Roles map to the same Role Mappings as OIDC.

Enter roles and entitlements to preview what permissions would be applied, without affecting any real user. 


                

            


            
            

                

                    

                        

                            
                            
                        

                        

                            
                            
                        

                    

                    

                        
                    


                    

                        

                            
                            
                            

                                Authoritative overwrites every covered permission on each login — anything not granted by an entitlement or role mapping is set to off / cleared. Backwards-compatible with all existing setups.
                                

                                Respect existing keeps that behavior when entitlements are present, but in the role-only path leaves any field the matched mappings didn't explicitly grant (and no deny mapping touched) at whatever Jellyfin already has on the user. Use this when you want roles to bootstrap a user and Jellyfin admins to manage the rest.
